## 产品决定

Telegram 机器人私聊成为主入口：每日一条总览，重要邮件及时提醒，详情按需展开。
暂时停用 Conversation / Todo / Read later 全部跟进能力；本轮不迁移跟进、不引入 Topics、Mini App、Calendar 或自由对话。
已有 SQLite 跟进记录、邮件快照和 Discord Forum 帖子保留，不自动搬迁或清理。
Gmail 保持只读，保留账号 ID、History cursor、分类结果、去重键和现有分类规则。
这次不改分类算法，也不把正在进行的微批分类工作合并进平台迁移。

## 用户体验

| 场景 | 目标行为 |
| --- | --- |
| 每日摘要 | 沿用当前时区与时间；发送一条短总览，显示日期、账号和分类计数 |
| 查看分类 | 点“待处理 / 通知 / 课程 / 行政”展开该类邮件，分页编辑同一条详情消息 |
| 查看邮件 | 显示账号、发件人、标题、摘要、注意点、建议操作和有用链接 |
| 查看正文 | 用户再次点击后读取本地七天缓存并分页；不在点击路径访问 Gmail |
| 缓存过期 | 明确提示已过期，保留打开 Gmail 的入口，不重新抓取正文 |
| 紧急邮件 | 单独发送简短提醒，带“查看详情”和“打开 Gmail”，保持现有分类规则 |
| 修改语言 | `/summary_language English`，复用当前校验和持久化，只影响未来摘要 |
| 查询状态 | `/status` 显示最近同步、最近成功投递、待重试数量，不显示邮件正文或凭证 |
| 手动查看 | `/today` 打开当天已保存的总览，不重新分类、不修改定时投递状态 |
| 运行故障 | 可选私有运维群，保留告警去重与冷却；默认不发送邮件正文 |

私聊默认只主动发送总览和紧急提醒；分类列表与正文都按需展开，避免刷屏。
普通详情消息会保留在 Telegram；本地缓存七天过期不等于已发送内容自动删除。
本轮不把临时消息或新式富文本组件作为依赖；正文复制量由用户点击控制。

## 实施顺序与验收

### 1. 分离消息投递与邮件处理

- 在 `src/notifications/` 建立小型接口，覆盖 digest、realtime、operational alert 三种投递。
- 将 `digest.ts`、`alerts.ts` 的 Discord 直接调用改为注入边界；平台负责排版与发送。
- 用户按钮、分页、命令仍属于各平台，不抽象为通用聊天框架。
- 先用现有 Discord 适配器接线，保持输出行为；不改 Gmail gateway 或分类器。
- 配置使用 `MESSAGING_PROVIDER=discord|telegram`，初期默认 Discord；只校验当前平台凭证。

验收：fake notifier 可验证摘要、提醒与故障；已有 Gmail 只读和去重测试继续通过。

### 2. 为通知增加可恢复投递

原流程先保存分类再推送；推送失败后，下次会因“已处理”跳过该邮件。投递状态单独保存后，worker 可以补发提醒而无需重新分类。

- 新增 SQLite outbox，状态至少为 `pending | sending | sent | failed`，记录重试次数、下次尝试时间和平台消息 ID。
- 分类结果与紧急提醒任务在同一事务提交；旧分类记录不因迁移自动补推。
- 每日总览使用稳定任务键：平台、目的地、时区下的日期；重复 cron 不创建第二个任务。
- 若总览必须分片，为每片记录任务键和投递结果，只重试未成功的片段。
- worker 以原子认领处理任务，启动恢复中断的认领，防止 cron 重入或两个进程同时发送。
- 对超时、429、5xx 实施有上限的退避；遵守 `retry_after`，400/403 等永久错误单独报告。
- 运维告警保留冷却；投递告警失败不递归创建更多告警，最终回落本地日志。
- 明确采用至少一次投递：外部发送成功但本地落库前崩溃，仍可能产生重复，不能承诺绝对一次。

验收：网络失败后不重跑分类即可补发；重启保留待发任务；重复 cron、部分成功和永久错误有测试。

当前 worker 启动时检查待发任务，之后每 5 秒检查一次。每次 HTTP 请求超时为 20 秒，未完成的认领在 2 分钟后可重新领取。暂时性错误最多尝试 6 次，429 会按 Discord 给出的等待时间暂停队列。`digest:once` 尝试当前到期任务，延迟重试由 daemon 或后续运行处理。

### 3. 接入 Telegram 私聊与权限

- 用 BotFather 创建独立 Hedwig bot；用户先 `/start`，之后才能接收主动提醒。
- 推荐一个维护活跃的 TypeScript bot 库（实施前核对官方文档）；outbox 仍由 Hedwig 管理。
- 使用长轮询，不新增 HTTP 服务、端口或 Tunnel；启动时检查已有 webhook 并明确报错，不静默覆盖。
- 配置 `TELEGRAM_BOT_TOKEN`、`TELEGRAM_OWNER_USER_ID`、`TELEGRAM_CHAT_ID`、可选 `TELEGRAM_DEBUG_CHAT_ID`。
- 所有邮件命令和回调同时校验 owner ID、私聊类型和目的地；用户名不作为身份依据。
- 运维群仅用于输出故障；群内不允许查询邮件，也不自动向发来 `/start` 的账号发送邮件。
- 持久化 update offset/去重状态，成功处理或可靠入库后再确认；同一 token 只运行一个 poller。
- 回调使用短、不透明的本地 token，映射邮件和分页状态，绑定 owner 与 chat；不塞入完整邮件 ID 或正文。
- 先确认按钮回调，再执行详情处理；缓存失效、重复点击、旧 token 都返回明确提示。
- 配置可脱敏检查；Bot token、OAuth token 和邮件正文不得写入错误日志。

验收：非 owner、群聊、伪造和过期回调无法读取内容；重启不重复执行已处理交互；权限由 fake update 测试覆盖。

已用 grammY 调用 Bot API，Hedwig 自己保存轮询 offset。生产服务已验证 `/start` 配对和回执。

### 4. 实现摘要、预览和命令

- 每日摘要生成时保存日期、分类顺序、邮件引用和总览文本快照；历史按钮读取该快照。
- 分类分页、正文分页分别编辑原详情消息，返回时恢复原页，避免点击产生大量新消息。
- 普通文本按 Telegram 限制安全切分；统一转义邮件内容，不将邮件 HTML 直接作为排版执行。
- 关闭自动链接预览，控制有用链接数量；保留多账号 Gmail 导航。
- 复用 `getCachedEmailPreview` 和语言设置；命令名改用 Telegram 支持的下划线格式。
- `/today` 复用当天快照；尚无快照时从 SQLite 生成只读视图，不触发 Gmail 或 LLM。
- 为 token/快照设定清理周期，并为正文缓存过期提供 Gmail 跳转；清理不删除长期分类记录。

验收：长邮件、中文、emoji、特殊字符、多账号、空摘要、缓存过期和跨日分页均有测试。
断言总览只主动投递一次；分页不重新分类；语言修改不重写历史摘要。

工作区实现会在同一条 Telegram 消息中切换总览、分类、邮件详情和正文。当天的定时摘要生成前，`/today` 从 SQLite 生成临时视图，生成后则读取当天的快照。快照和按钮保留七天，在服务启动、生成总览以及请求 `/today` 时清理过期记录。

## 回滚

观察期保留 Discord 适配器，出问题时停止 Telegram daemon，再切回 Discord 配置启动。
SQLite 只做向后兼容的新增表/索引，不删旧字段；通常无需恢复旧库，避免丢失切换后的邮件记录。
旧版本若无法读取新库，先停止服务并备份当前库，再按迁移方案处理，不能直接覆盖成旧快照。
Discord 清理完成后，回滚通过保留的发布版本和兼容配置恢复；每次起停与配置变化记 `infra log`。
